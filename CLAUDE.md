# Phase 6: Staff Officer Prompter Rebuild State

This file tracks the transition of the Staff Officer project from a Gemini-dependent script to a **Pure Local + Multi-Role** architecture (English-only codebase), as mandated by the Phase 6 implementation plan.

## 🔴 Pending Tasks (P1 — deferred, not yet addressed)
- **Re-measure live throughput under real load**: The fanless thermal lever is now addressed by auto-selecting `FANLESS_MODEL` on Airs (see Completed). Levers already resolved: incremental Silero VAD was benchmarked and DROPPED (VAD ≈ 0.3% of decode cost — not the bottleneck); `NPU_LOCK` is intentionally KEPT (no parallelism gain on a single GPU, removing it only risks Metal crashes). Open item: confirm on a real long meeting that medium on the Air actually keeps up — the model benchmark used short, clean TTS clips, so real noisy 28s windows were never measured end-to-end. The durable-capture + offline retranscribe path is the lossless backstop regardless.

## 🟡 Backlog (P2 — no concrete use case yet, build on demand)
- **Speaker diarization for single mixed-source files**: Live capture already separates speakers by physical input (Speaker mic vs Participant/BlackHole), so role labels are free and exact — diarization is NOT needed there. It only matters when a SINGLE mixed-channel recording is fed to batch mode (e.g. a downloaded podcast, or a phone recording where everyone shares one channel), where `-at` currently yields one unlabeled transcript. Plan: run a diarization model (`pyannote.audio`; reuses the existing PyTorch already pulled in by silero-vad, but needs a HuggingFace-gated pretrained model download) to get "who spoke when", merge with Whisper word timestamps for a speaker-segmented transcript, then optionally use an LLM to map anonymous SPEAKER_xx labels to roles (host/guest) from linguistic cues. Adds a real model dependency; deferred until a scenario needs it. Limits: overlapping speech, similar voices, crosstalk, and music/noise degrade accuracy.
- **Auto-stop / idle detection**: the live engine never self-terminates — `start_recording()` runs until the UI stop button calls `stop_recording()`, so after a meeting ends it keeps looping (and post-meeting room noise can keep transcribing). This was deliberately omitted so a natural mid-meeting pause cannot kill the session, but a long-idle auto-stop (e.g. N consecutive minutes of VAD silence on BOTH tracks) would prevent the "still running after the meeting ended" situation. Needs a conservative idle threshold so it can never trigger mid-meeting.
- **✅ Transcript → LLM summary layer (local-first) — IMPLEMENTED (P2#1)**: Done via `mlx-lm` (in-process, no daemon — sibling of the existing `mlx-whisper`), NOT Ollama/llama.cpp. `src/summarizer.py` adds `build_summary_prompt` (pure, grounded four-section TL;DR/Key Points/Decisions/Action Items prompt with a no-hallucination rule) and `summarize()` (lazy-imports `mlx_lm`, loads `mlx-community/Qwen2.5-3B-Instruct-4bit` overridable via `SUMMARY_MODEL`, fails soft to an error string). `retranscribe.py --summarize` writes `summary.md` (session) / `<out>.summary.md` (single file) after the transcript; the no-summary path never imports `mlx-lm`. Ctrl+C now auto-spawns a fully detached `retranscribe.py <session> --summarize` (see below). Real end-to-end generation verified on a bilingual fixture. Q&A-over-transcript and the YouTube-caption variant remain future work on this same layer.
- **(historical design note) Transcript → LLM summary / Q&A layer (local-first)**: The offline path already produces a clean, speaker-labeled `transcript.md`. Adding a summarization + Q&A step on top of it yields a NotebookLM-style capability (NotebookLM itself just summarizes a video's transcript with an LLM — it does not "watch" the video). Local-first: wire a LOCAL LLM (Ollama / llama.cpp) over the transcript to preserve the pure-local, no-cloud, no-API-key stance; a cloud LLM (Claude Messages API) is the higher-quality alternative but breaks that stance, so make it opt-in, not the default. This slots directly after `retranscribe.py` — same source-of-truth transcript, one new summarize layer. Note: a future "summarize a YouTube video" feature is the same pattern — fetch the YouTube captions first (fall back to download-audio → Whisper only when no captions exist), then run the same summary layer; Claude/Gemini have no native video input, so video understanding is always transcript-based plus optional frame sampling.
  - **End-trigger / finalize design (decided)**: Do NOT couple the summary to a web-UI stop. The primary graceful end is **Ctrl+C / SIGINT** in the Streamlit terminal — the operator's actual habit.
    - **✅ SIGINT hardening (DONE)**: `stop()` now finalizes the durable WAV **first and fast** — clear `is_running` → close the mic stream → drain+join the capture writer (≤~5s) → close the WAV header — BEFORE any wait on the Whisper worker, so even a second impatient Ctrl+C leaves a properly-closed header. The heavy `_final_flush` decode is now **skippable via a `flush` flag** threaded `stop(flush=)` → `stop_recording(flush=)` → `cleanup_resources()` (which passes `flush=False`); on the SIGINT/atexit path the residual decode is skipped and the worker join is short (2s vs 30s), so Ctrl+C returns in seconds. The complete transcript is still rebuilt offline from the WAV by `retranscribe.py`. (Live Ctrl+C smoke test on a real mic still pending.)
    - **✅ Detached summary (DONE)**: `cleanup_resources()` now, AFTER the fast `stop_recording(flush=False)`, spawns a FULLY DETACHED `subprocess.Popen([sys.executable, retranscribe.py, <session_dir>, "--summarize"], start_new_session=True, ...)` that survives parent exit and logs to `recordings/<id>/auto_summary.log`. Guards: gated by `AUTO_SUMMARIZE_ON_EXIT` (default on; `_auto_summarize_enabled` in summarizer.py), only when `g_state.recordings_dir` exists, once per process (`_summary_spawned`). The WAVs are closed by the preceding fast finalize, so the child reads complete files. Ctrl+C stays snappy (no wait on the child); the on-demand `retranscribe recordings/<id>/ --summarize` command also exists.

## 🟢 Completed Steps
- Defined Phase 6 Implementation Plan.

- Updated `.env` to support `MULTILINGUAL_MODE`.
- Created this `CLAUDE.md` to track progress!
- **Knowledge Compiler (`src/build_index.py`)**: Parses `.md/.txt` into `knowledge_index.pkl` vector embeddings.
- **Pure Local RAG (`src/local_advisor.py`)**: Loads the vector index and runs cosine-similarity trigger matching. `gemini_advisor.py` deprecated/removed.
- **State & UI Refactor (`app.py`, `global_state.py`)**: English-only artifacts; `?role=speaker` / `?role=staff` routing; staff manual-broadcast UI; auto-scroll UX limited to the latest ~5 lines.
- **Anti-data-loss durable raw-audio capture (`src/transcriber.py`, `src/global_state.py`)**: Each session writes one lossless mono 16kHz/16-bit WAV per track to `recordings/<session_id>/<Track>.wav` via a dedicated writer thread off the audio callback, plus a `_final_flush` that decodes residual audio at shutdown. A whole-utterance exact-match hallucination filter (`_acceptable` / `_normalize_phrase`) replaces the old substring filter, so real speech containing "謝謝"/"thank you" survives.
- **Offline / batch re-transcription (`src/retranscribe.py`)**: Ungated, loss-free engine. `python3 src/app.py -at <audio> -o <out.txt>` (single file; `app.py` routes batch away from Streamlit before importing it) and `python src/retranscribe.py recordings/<session_id>/` (per-track WAV merge → `transcript.md`/`.txt`). Channel-split limited to 16kHz 16-bit WAV to avoid new pip dependencies.
- **Local LLM summary layer (`src/summarizer.py`, `retranscribe.py --summarize`, `app.py` detached auto-spawn)**: `mlx-lm` (added to `requirements.txt`) generates a grounded four-section summary from the finished transcript. Pure `build_summary_prompt`; lazy-`mlx_lm` `summarize()` (`SUMMARY_MODEL` env, default `mlx-community/Qwen2.5-3B-Instruct-4bit`, fails soft); `--summarize` writes `summary.md`/`<out>.summary.md` without ever failing the transcript step. Ctrl+C auto-spawns the detached pipeline (`AUTO_SUMMARIZE_ON_EXIT`, default on). The no-summary paths never import `mlx-lm`.
- **BVA unit tests (`tests/unit/test_transcriber.py`, `tests/unit/test_summarizer.py`)**: Pure-function boundary tests for `_acceptable`, `_float_to_int16`, `slug_track_name`, `should_run_batch`, `_wants_word_timestamps`, `is_fanless`, and `resolve_default_model` — no model load. The summarizer suite adds boundary tests for `build_summary_prompt` (empty/short/multi-line/None), `resolve_summary_model`, the `AUTO_SUMMARIZE_ON_EXIT` flag parser, the `--summarize` argparse flag, and a lazy-import guard proving `import summarizer` does not pull in `mlx_lm`.
- **`.gitignore`**: Added `recordings/` (durable capture + generated transcripts are not committed).
- **Window-mode `word_timestamps` skipped ("1a")**: `_decode` now passes `word_timestamps` via `Transcriber._wants_word_timestamps(mode)` — True only for `localagreement`, False for `window` — so window-mode passes no longer pay the unused word-alignment cost.
- **Hardware-aware model auto-select (2c)**: `resolve_default_model()` picks `FANLESS_MODEL` (`whisper-medium-mlx`) on fanless Macs — MacBook Air, detected by `system_profiler` marketing name, not board id — and `DEFAULT_MODEL` (`large-v3-turbo`) otherwise; an explicit `WHISPER_MODEL` always overrides. Chosen from an M4-Air benchmark: medium matched large on clean-speech WER/CER, ran ~1.5x faster, and runs cooler on the fanless chassis. Offline `retranscribe.py` keeps the larger `DEFAULT_MODEL` for best one-shot quality. Note: `medium-mlx` downloads (~0.8GB) into `.hf_cache` on first live run.
